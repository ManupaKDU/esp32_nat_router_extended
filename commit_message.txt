🔒 Fix buffer overflows via strcpy

🎯 What:
Replaced unbounded `strcpy` and `strcat` with secure `snprintf` in `src/urihandler/otahandler.c`. Updated `getOtaUrl` signature to pass destination buffer sizes safely.

⚠️ Risk:
The use of unbounded `strcpy` and `strcat` functions poses a buffer overflow risk. If a maliciously crafted payload (e.g. via an injected custom URL parameter during OTA updates) exceeded the destination buffer size, it could cause stack corruption leading to application crashes (DoS) or potentially arbitrary code execution.

🛡️ Solution:
Replaced all occurrences of `strcpy` and `strcat` in `src/urihandler/otahandler.c` with bounded `snprintf` operations. Where necessary, function signatures like `getOtaUrl` were updated to explicitly accept buffer size bounds (`size_t`), and caller sites were adapted to pass these bounds using `sizeof(buffer)`.
